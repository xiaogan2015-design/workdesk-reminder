# 工笺 Windows 事项记录与提醒设计

> **文档编号**　GONGJIAN-SDD-DESKTOP-WORK-001　**可见性**　公开　**版本**　V0.1<br>
> **状态**　待评审　**日期**　2026-11-25<br>
> **关联文档**　[需求与验收](./requirements.md)

**关键词**　Windows、WPF、托盘、截止时间、日报、周报、本地存储

工笺面向在 Windows 上记录待办和工作总结的个人用户。关闭主窗口后需要继续提醒，交付物为单个可执行文件。由窗口或网页标签页直接持有定时器，会让提醒依赖界面是否仍然打开。应用通过一个 WPF 进程管理界面、托盘、提醒和本地数据。

## 1. 约束与目标

| 编号 | 约束 | 来源 |
| --- | --- | --- |
| C1 | Windows EXE，可离线运行，免安装 | 产品交付要求 |
| C2 | 隐藏主窗口后继续提醒，退出应用后停止 | 截止和总结提醒场景 |
| C3 | 数据保存在当前 Windows 用户目录，用户可补记完成时间并编辑历史总结 | 记录和回看场景 |
| C4 | 界面采用清晰的侧栏、卡片布局和分组表单 | 网页式视觉要求 |

个人使用、单机保存。首版范围为待办、总结、提醒及其设置。

## 2. 选型

| 方案 | 评价 |
| --- | --- |
| WPF + .NET Framework | 可利用 Windows 现有运行时和编译器，原生支持窗口、托盘互操作和 XAML 样式。单 EXE 可交付，适合当前工作区。 |
| Electron | 可复用 HTML/CSS，需要额外下载并打包 Chromium 和依赖。 |
| 浏览器页面 | 易于制作界面，提醒生命周期受浏览器控制，单独交付 EXE 仍需桌面外壳。 |

采用 WPF。项目使用 Windows 自带 C# 编译器，将 XAML 和应用图标嵌入 EXE。

## 3. 结构与行为

```text
WorkDesk.exe
  ├─ Program                  应用生命周期、托盘、定时器与弹窗
  ├─ MainWindow / Editors     工作台、总结、设置、事项编辑
  ├─ WorkState                事项与总结模型、排程及校验
  └─ StateStore                本地 JSON 读取、原子写入与备份读取
                                   │
                                   ▼
                    %LOCALAPPDATA%\WorkDesk\state.json
```

### 3.1 数据结构

| 数据 | 主要字段 | 约束 |
| --- | --- | --- |
| 事项 | `Id`、`Title`、`Notes`、`DueUtc`、`LeadMinutes`、`CompletedUtc`、`ReminderShown` | `Id` 唯一。`CompletedUtc` 有值即为完成。截止和完成时间保存为 UTC，界面转换为本地时间。 |
| 总结 | `Weekly`、`Period`、`Text`、`UpdatedUtc` | 类型与周期日期组合唯一。日报使用本地日期，周报取本地周一。 |
| 提醒设置 | `DailyEnabled`、`DailyMinute`、`WeeklyEnabled`、`WeeklyDay`、`WeeklyMinute` | 提醒时刻是本地时间自午夜起的分钟数。 |
| 文件根节点 | `Version`、事项列表、总结列表、设置、上次日报和周报提醒周期 | 加载时检查版本和必要字段。首版文件版本为 `1`。 |

### 3.2 保存与提醒

界面事件和提醒检查由同一 WPF Dispatcher 串行处理。一条用户操作在状态写入成功后才刷新界面。保存时先写同目录临时文件并落盘，再原子替换主文件并保留前一版备份。主文件无法读取时尝试备份，并在界面提示恢复。两份都无法读取时显示数据路径并退出，给用户保留原文件。

```text
时钟每 5 秒检查一次
    ├─ 事项：未完成，未提示，当前时间达到截止时间减去提前量
    ├─ 日报：今天已到设定时刻，今天未保存且未提示
    └─ 周报：今天是设定星期且已到时刻，本周未保存且未提示
           │
           ▼
      保存本轮提醒标记 ──成功──► 弹出提示 ──点击──► 工作台或对应总结
           │
           └─写入失败──► 提示保存问题，下一轮重试
```

同一批事项可合并成一个弹窗，工作台仍列出各自的截止状态。应用优先避免重启后重复弹窗。若在写入标记后、弹窗出现前被强制结束，该次提醒可能只在工作台上通过待办状态体现。

### 3.3 窗口生命周期

主窗口关闭时隐藏，托盘菜单负责重开和退出。通过 Windows 用户会话内的单实例锁避免两个进程并发写同一数据文件。再次双击 EXE 时唤起已有窗口。登录启动使用当前用户的 Windows 启动项，以托盘模式启动。打开该设置后移动 EXE 时，需要重新设置启动路径。

## 4. 实现顺序与验证

| 里程碑 | 交付 | 验证 |
| --- | --- | --- |
| M1 · 需求与设计 | 需求、页面流程、数据与提醒设计 | 审阅 R1–R7 和 A1–A6 的映射，确认提醒时间和关闭行为。 |
| M2 · 事项与存储 | 工作台、事项编辑、完成时间、JSON 持久化 | 自测排序、筛选、补记完成、备份恢复。通过桌面入口执行 A1、A2。 |
| M3 · 总结与提醒 | 日报、周报、托盘、弹窗和设置 | 自测时间边界、跨周、已写跳过及重启去重。用短间隔执行 A3–A5。 |
| M4 · EXE 打包 | `dist/WorkDesk.exe`、构建与自测命令 | 在 Windows 双击产物执行 A6，记录包大小和 SHA-256。 |

每个里程碑通过对应检查后提交到 GitHub 的 `main`。免安装版使用 Windows 已安装的 .NET Framework 4.8 或 4.8.1。弹窗依赖当前 Windows 桌面会话和应用进程持续运行。
